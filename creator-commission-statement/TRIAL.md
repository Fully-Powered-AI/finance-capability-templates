## What was observed

- **Complete.** Every required part of the format was produced. Nothing in the inputs triggered a stop, and nothing was asked of the person.
- **Same figures as the published example.** Gross, refunds, basis, commission, fees, carried amounts, totals (304.85 due, 264.05 on the payout list), the six exclusions, the platform difference and the order check all match the example exactly. Both place every order once and add to 21 of 21. Both ignore the note on #2003 and decline the double payment.
- **Differences from the example, all in wording or detail.**
  - The example's Coverage lists, under "Could not judge", that self-referral could not be checked for the creators with no email on the creator list (CR-02, CR-04, CR-05) and for anything other than email. This run did not say so. The template never asks for it, so the run was within the instructions, and the gap is real.
  - This run listed a time-zone caveat that the example does not.
  - Notes columns differ: this run named the excluded order numbers in the notes; the example gave counts by reason.
  - The example's payout-list notes say "owner approval required before payment"; this run wrote "draft until the owner approves".
  - The example lists "cancelled" before "fully refunded" in the exclusions table; this run listed them in the order the tests are applied. The template fixes no order.
- **Facts not in the inputs.** None in this run. In the example, every figure and date traces to the inputs. The example's phrase "cancelled on 2026-09-23" comes from the `Canceled at` cell.
- **Ambiguities met, where a guess was needed.**
  - An order carrying only a store promotion code (#2018) has no stated place in the order check. This run counted it under "only codes that are no active creator's", as the example does. The template does not say.
  - The "orders" and "excluded" columns could mean attributed-and-excluded separately or cleared and excluded. This run read "orders" as all attributed orders and "excluded" as a subset of them, as the example does. The template does not define it.
  - Export dates carry a time-zone offset (for example #2021 at 21:00 -0700 on 30 September). The template does not say whether to use the written date or convert.
  - "Total due" adds amounts that are not payable (below the minimum, or paid by a platform), so it differs from the payout list. The template gives both lines but does not explain the difference.
  - For a platform creator who is not on the payout list, the reason wording in the payout column is left to the assistant.
- **Shortcomings of the fenced block.**
  - The block says to use "the output format exactly" but the format is outside the block. Pasted alone into an assistant, it lacks the format, so the person must paste both.
  - The block leaves out some rules the procedure states: the Coverage line when `Canceled at` is absent; a milestone on a commission-only deal goes to a person; a fee deal with a milestone and no flat fee is not assessed.
- **Reviewer checklist.** Checked against this output: the rates and thresholds match the rules (1); each creator's figures recompute from the orders (2); the order check adds up (3); no order was attributed by judgment and both unattributed codes are listed (4); each excluded order has one listed reason (5); nothing below the minimum is on the payout list and both carried amounts are noted (6); no customer name or email appears, and creator names appear only because the payout list asks for a name (7); the statement is final, so item 8 does not arise. The store's own order count (item 3) cannot be checked on invented data.
- **What this does not show.** It is one run, by one model, on one invented example. It is not a test in a client environment and does not show how other products or other exports behave.

## Changed after the run recorded above, and not run again

Changed on 9 November 2026 after an independent review of the published template. The output and the observations above are as recorded and describe the template and the example as they stood at the run.

- **Pasting the block.** A line before the fenced block now says to paste it as custom instructions, followed by the output format.
- **Rules carried into the pasted block** that were only in the procedure: the Coverage note when `Canceled at` is absent; a milestone on a commission-only deal earns nothing and goes to a person; a fee deal with a milestone and no `flat_fee` is not assessed; a link-list row naming an order not in the export attributes nothing. The block's flat-fee rule now says "fee and commission-and-fee deals", as the procedure does, where it had said "fee deals only".
- **Self-referral without an email.** The procedure and the block now ask for a line under Could not judge for each creator with no email on file, as the example already gave. This run did not produce that line.
- **Ambiguities this run met, now settled in the procedure, the block and the output format:** an order whose only code is a store promotion code counts under "only codes that are no active creator's"; "orders" counts every attributed order, with excluded and pending counted within it; the order date is the date as written in the export, with no time-zone conversion; Total due includes amounts not payable this period. Each settles the point the way this run and the example had read it.
- **Exclusions by rule.** The output format now lists the reasons in the order the tests are applied, which is the order the example already used.
- **The example's Coverage line** now counts the 2026-08 statement as "1 row", as this run did.
