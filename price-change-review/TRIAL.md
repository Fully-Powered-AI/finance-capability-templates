# Price change review: tried on its example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-10

This run used only the invented inputs from the worked example (`public/example.md`): the settings, the sales export, the cost export, the proposed changes, the five competitor prices, the one earlier price change and the price commitment for Tallowmere Soap Works, an invented business. No client data was used. The assistant that ran it did not write the template. It followed the instruction block and the output format in `member/template.md`, and it did not read the example's output until its own review was finished.

## What was observed

- **Every required part was produced.** All ten sections of the format were filled, the closing line is present, and no item was left out. Nothing in the inputs required the assistant to stop: every header matched, no cost was zero, and the proposals were all rises, so one range served.
- **Checks.** The figures were worked by hand from the instructions and then recomputed with a short script. Every item figure, total, break-even and percentage agreed. The reviewer checklist passes on all eight points: figures match the exports, the scenarios use the stated range and today's cost, the totals add up from the rounded item figures, the break-evens fall in the right direction, the 149-day-old competitor price is marked OLD and left out of the comparison, and nowhere does the review say which price to choose.
- **Difference from the published example.** The figures, the order and the three questions are the same as the example's. The wording differs in small ways. The example is laid out with bold headings and bullets; this run used the template's plain-text layout. In the earlier price change, the example adds "such as the season"; this run did not, because neither the inputs nor the format supply a reason. In Data notes, the example words the gift set commitment as a sentence (the shops "keep this year's price until 31 December 2026"); this run used the shorter bracketed form. The second question names that Competitor C has no in-date price for bar soap; the example's question does not.
- **Facts not in the inputs.** In this output, none. In the published example output, one: "such as the season" gives a reason for the earlier price change that the inputs do not state.
- **Where the instructions needed a judgment.** These did not change the result here, but another run could differ.
  - The margin floor is checked only against today's margin. The format has no place to say whether a proposed price lifts an item over the floor, so the review is silent on it.
  - Nothing says whether BELOW FLOOR compares the rounded or the unrounded margin percentage. Both give the same answer on these inputs.
  - The format has no line for an item with no proposed change inside the proposed-changes section other than "No change proposed", so nothing is shown for how today's range would treat it. This run held it as today, as the instructions say.
  - The picture's deltas could be taken from the rounded item figures or the exact ones. This run summed the rounded item figures, which is what the rounding step asks for.
  - Whether a competitor with only an old price for an item (Competitor C) needs a question is clear from step 13, but the instruction block's wording ("that competitor has no in-date price for the item") took a second reading.
  - The fixed-format placeholders in square brackets, such as "[your competitor age limit, default 90 days]", appear in the procedure but not in the format, so the assistant has to see that they are settings.
  - The earlier price change falls outside the sales period (1 March 2025), so the "inside the period" note and question were correctly not triggered. The template does not say what to write about an earlier change that is outside the period beyond the standard label.
- **Things it declined or stopped for.** None. The inputs did not ask for a price recommendation, a change to any record, or a competitor lookup, so those refusals were not exercised.
- **Not covered.** This was one run on one invented example, in one product. The acceptance tests for a missing header, a zero cost, a price cut, a competitor price with no date, an earlier change inside the period and the three refusals were not run. The template has not been tested in a client environment.

## Edits made after this run

After this run and an independent review, the same day, the template and the example were edited. These edits were not run again. None changes a figure, a stop or a section on these inputs, and the output recorded above conforms to the edited wording; the record above is unchanged.

- BELOW FLOOR now compares the margin percentage rounded to one decimal place, and the proposed-changes line can now mark "New margin BELOW FLOOR." when a proposed price leaves the new margin under the floor. On these inputs every new margin is above the 50% floor, so nothing new is marked.
- The pasted instructions now carry three rules that were already in the procedure: rows for the same item in the sales export are added together; the same item listed twice in the proposed changes stops for a question; a cut that leaves a margin of zero or less is written as "no rise in units holds today's gross profit". None applies to these inputs.
- The pasted instructions now also name a login code, beside a password, among the things not to repeat, and one line was re-wrapped.
- The Inputs now say that items in square brackets are settings.
- The example no longer adds "such as the season" to the earlier price change, and its Data notes and second and third questions now use the wording this run used.
- The template's version notes and the profile no longer say it has not been tried.
